Milestone 002: Atomic Chase Evaluation Capture

Give an external controller one camera frame and one bounded evaluator shadow from the same Chase state without advancing playback or exposing simulator-only geometry through the sensor interface.

Status: active - implementationStarted: 2026-07-20Delivery model: integration branchController sensor: image-only

High-Level Objective

Frame Identity

A capture response identifies one simulation frame by game, simulation epoch, and frame index. Its rendered image and evaluator shadow are built from the same frozen observation record.

Privilege Separation

The controller receives the camera artifact only. Evaluator facts are returned separately for measurement and are never passed to the controller as perception.

Completion Usage

Request Atomic Evaluation

Starting state: Play is loaded with Chase and a frontend is connected.

Proposed execution: simeval ui play-evaluation-capture --actor chaser --out-dir ./evaluation-captures.

Success signal: SimEval writes one image and one metadata file with a shared capture ID and gameId + simulationEpoch + frameIndex; metadata reports playback.advanced=false and carries a bounded evaluator-only control reference for that capture.

Validate A Controller Flow

Starting state: the Play frontend tab is active and SimEval can reach its WS endpoint.

Proposed execution: npm run play:chase:evaluation:capture -- --out-dir /tmp/chase-evaluation-capture.

Success signal: the fixture reports all checks passed for same-state repetition, later-frame movement under WS input, changed image evidence, reset-safe identity, sensor/evaluator separation, and bounded controller-reference persistence.

Inspection: open validation.json or compare the persisted before and after images.

Baseline

M002 / 01 through M002 / 03 are accepted: the repository has a frozen same-state image/count bundle, runtime-owned reset epochs, generic public Play transport, SimEval persistence, strict offline validation, and retained before/repeat/move/reset evidence. Cross-repository validation against auto-driving Milestone 005 found one remaining blocker: the evaluator contains visible counts but no same-capture control source or action reference, so auto-driving would still have to pair the image with stale play_debug data whose observed lag is 15–29 frames.

Atomic Capture Contract

interface AtomicEvaluationCapture {
  captureId: string;
  frameIdentity: {
    gameId: string;
    simulationEpoch: string;
    frameIndex: number;
  };
  playback: { advanced: false };
  sensor: { image: CameraImageArtifact };
  evaluator: {
    shadow: BoundedEvaluatorShadow;
    reference: BoundedEvaluatorControlReference;
  };
}

captureId identifies the actor capture artifact; frameIdentity identifies the simulation state across resets and persisted runs. The builder receives one frozen, visible-only capture record and one synchronously projected control reference. reference may contain only scenario ID, control source, phase, source action frame, normalized input, and normalized action. Obstacles, map cells, poses, actor identities, reasoning snapshots, and proposal collections remain forbidden. Both evaluator records are explicitly non-sensor and must never enter controller perception.

Scope Boundaries

In Scope

Capture identity, frozen visible-only source records, bounded evaluator count and control-reference policy, Play transport, SimEval usage, auto-driving evaluator consumption, and live-controller validation.

Out Of Scope

VLM interpretation, decision-model input changes, exposing global geometry to a controller, recording arbitrary world/debug snapshots, and changing vehicle behavior.

Risks And Controls

RiskControl
Image and evaluator describe different states.Project the reference synchronously with the image, preserve the source action frame separately, and reject future-frame references.
Frame indexes collide after reset.Keep the opaque simulation epoch in every frame identity and persisted evaluator artifact.
Evaluator data leaks into controller perception.Use separate sensor and evaluator envelopes with exact-key tests; auto-driving consumes reference only in its evaluator path.
Capture changes playback timing.Keep the builder pure and verify the frame counter remains unchanged.
Controller reference grows into a hidden debug/world dump.Whitelist normalized control fields and reject poses, map geometry, reasoning snapshots, and proposal collections.

M002 / 04 Evidence

Persisted Captures

Before and repeat are byte-identical frame-zero images with identical control references. After move is frame 164 in the same epoch, has changed image bytes, and reports WS authority. After reset returns to frame zero in a new epoch.

Machine Verdict

Validation JSON passes 31 of 31 checks, including exact control-reference shape, same-state persistence, and movement authority. The evidence notes record scope, interpretation, reproduction, and the browser-animation constraint.

Exit Criteria

  1. One public request returns a camera artifact and bounded evaluator data with one capture ID and one gameId + simulationEpoch + frameIndex frame identity.
  2. The request does not advance, pause, or reset the simulation.
  3. Sensor output contains no simulator-only geometry or evaluator facts.
  4. Evaluator output contains only documented count and control-reference fields, with no map geometry, poses, reasoning snapshots, or proposal collections.
  5. SimEval can persist the artifact and structured metadata for an external-controller run.
  6. Regression and live evidence prove before/after controller behavior without identity drift, including across simulation resets.
  7. Auto-driving consumes the atomic image/reference response and passes its live Chase frame-alignment gate without sequential play_debug pairing.
