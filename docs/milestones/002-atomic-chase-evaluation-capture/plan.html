Milestone 002: Atomic Chase Evaluation Capture

Give an external controller one camera frame and one bounded evaluator shadow from the same Chase state without advancing playback or exposing simulator-only geometry through the sensor interface.

Status: active - implementationStarted: 2026-07-20Delivery model: integration branchController sensor: image-only

High-Level Objective

Frame Identity

A capture response identifies one simulation frame by game, simulation epoch, and frame index. Its rendered image and evaluator shadow are built from the same frozen observation record.

Privilege Separation

The controller receives the camera artifact only. Evaluator facts are returned separately for measurement and are never passed to the controller as perception.

Completion Usage

Request Atomic Evaluation

Starting state: Play is loaded with Chase and a chaser simulation is paused or running.

Proposed execution: request a proposed play-evaluation-capture through the Play control protocol for chaser.

Success signal: one response contains an image artifact and evaluator shadow with the same game, simulation epoch, and frame index, without changing the simulation frame.

Drive A Customer Controller

Starting state: an external controller has received a previous camera artifact and owns the Chaser WS controls.

Proposed execution: send controller input, then request the next proposed evaluation capture.

Success signal: controller inputs affect later camera frames, while evaluator-only facts remain outside the controller sensor payload.

Automation path: structured protocol output can be saved by SimEval with image, capture ID, frame identity, and evaluator metadata.

Baseline

Chase can independently return a manual front-view PNG and debug state. Those calls can observe different animation frames, and a manual front-view record contains visible map facts used for rendering. There is no public same-state evaluation envelope or explicit controller/evaluator privilege boundary.

Atomic Capture Contract

interface AtomicEvaluationCapture {
  captureId: string;
  frameIdentity: {
    gameId: string;
    simulationEpoch: string;
    frameIndex: number;
  };
  playback: { advanced: false };
  sensor: { image: CameraImageArtifact };
  evaluator: { shadow: BoundedEvaluatorShadow };
}

captureId identifies the actor capture artifact; frameIdentity identifies the simulation state across resets and persisted runs. The builder receives one frozen, visible-only capture record. It may derive count-only evaluator measurements from that record, but must not expose obstacles, map cells, actor identities, actor positions, or decision/debug state through sensor. The evaluator shadow is explicitly labeled as non-sensor data.

Scope Boundaries

In Scope

Capture identity, frozen visible-only source records, bounded evaluator shadow policy, Play transport, SimEval usage, and live-controller validation.

Out Of Scope

VLM interpretation, decision-model input changes, exposing global geometry to a controller, recording arbitrary world snapshots, and changing vehicle behavior.

Risks And Controls

RiskControl
Image and evaluator describe different frames.Create both from one immutable capture source and assert equal game, simulation epoch, and frame index in regressions.
Frame indexes collide after reset.Keep the opaque simulation epoch in every frame identity and persisted evaluator artifact.
Evaluator data leaks into controller perception.Use separate sensor and evaluator envelopes with tests that reject simulator geometry from sensor output.
Capture changes playback timing.Make the builder pure and verify the frame counter is unchanged before public transport is added.
Evaluator scope grows into a hidden world dump.Keep its fields count-only and bounded to explicitly documented measurements derived from visible-only capture facts.

Exit Criteria

  1. One public request returns a camera artifact and bounded evaluator shadow with one capture ID and one gameId + simulationEpoch + frameIndex frame identity.
  2. The request does not advance, pause, or reset the simulation.
  3. Sensor output contains no simulator-only geometry or evaluator facts.
  4. SimEval can persist the artifact and structured metadata for an external-controller run.
  5. Regression and live evidence prove before/after controller behavior without identity drift, including across simulation resets.
